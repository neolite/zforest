zboard — server-driven доска на Zig

Анонимная imageboard: весь UI-стейт живёт на сервере, клиент — пассивный патчер. Суть — render groups: N браузеров с одинаковым видом делят один DOM-трекинг, один рендер и одну историю патчей.

1. Общая схема

  • Один рендер на группу, не на браузер. Сессии с равным (route, reply_to, name, sort) шарят Dom+History+revision — 32 lurker'а на треде = один buildView+diff на версию модели.
  • Клиент ничего не знает о состоянии. SSR → патчи → snapshot; DOM-опы fine-grained (text/attr/when/move), фреймворка нет.
  • Модель общая, сессии — проекции. BoardModel в памяти + write-through SQLite; мутация бампает global_seq, группы дедупят рендер по нему — кросс-таб fan-out бесплатно.

2. Ключевое: clone-on-fork

  • Зачем: snapshot пересобирает весь DOM — стирает focus и незасланные черновики. Fork клонирует stream lineage (rev + ring + tracked Dom), поэтому клиент продолжает получать patch-события с валидным курсором.
  • Предел: вход в существующую группу (cancel reply при живых lurker'ах, A→B→A) — всегда snapshot: ревизии чужой lineage несовместимы.

3. Доменка: лайки и сортировка

  • Лайки — таблица likes(kind, target, user, ts), PK запрещает второй голос с того же zfxu-аккаунта. In-memory: like_counts (id → счётчик, id-пространство постов и комментов общее) + liked_by (композитный ключ для O(1) проверки toggle). Кнопка ▲ N на постах и комментах, тоггл через POST /action {action:"like", arg:"c12"/"p3"}.
  • Сортировка — per-session поле sort ∈ {new, top}: new — новые сверху (дефолт), top — по лайкам (tie → новее выше). Сорт — часть group key: переключение = fork/join, переупорядочивание уходит как move-опы keyed-list diff'а. Дети тредов всегда хронологические — сорт применяется только к топ-уровню.
  • Персистентность: всё write-through в SQLite (board.db, WAL); лайки переживают рестарт, индексы пересобираются при load.
Деплой: статический бинарь ~5–12 MB на exe.dev VM (zboard.exe.xyz, FRA). Порты: 8080 todo · 8081 board (public) · 8082 zmon · 8083 zcar — exe.dev шарит один публичный порт, остальные по exe.dev-логину.
